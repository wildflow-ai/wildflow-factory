# 野生流动内容工厂

wildflow-factory 是独立的内容生产开箱包，以定时、批量和持续自动化生产为主要使用方式。
当前先做内容工厂，首版聚焦内部 AI 图书带货的视频生产；长期仍覆盖图文、音频、视频及其组合。
内容工厂从一开始就是独立方向，在业务和产品上与既有“视频自动化”线并行；首版采用视频生产场景，
不改变两者的独立边界。

自动化视频生产由一组 Skill 和对应的自动驱动流程组成。Harness 是基于 DeepSeek Harness 搭建的
插件系统基础，Skill 提供专业任务方法，自动驱动流程串联各阶段。模型能力主要使用自己的 WildFlow
模型服务。自有内容工作台留待后续，先积累业务工作台的交付经验再归纳产品；当前经验仍不足，
具体体系尚未搭建。

本页提供可独立阅读的当前方向；跨仓背景见 [内部 ADR-0015（需主仓权限）](https://github.com/wildsyn/wildflow/blob/main/docs/adr/0015-internal-factory-first.md)。本仓负责工厂的具体实现与验收。

## 当前阶段与首版

首版围绕内部图书带货任务，把文案改写、分镜、绘图提示词、生图、配音和视频合成连成可重复执行的
流程，产出供人工检查与修改的视频。先把这条内部流程打磨稳定，再扩大内容场景。

Storybound 爆款流水线交接包是现有流程与规则的打磨来源，包含脚本、提示词装配和输出约定。
该交接包尚未迁入本仓，也没有本仓 Harness 插件安装、Skill 发现和调用的验证证据。
包内记录的运行结果不能代替本仓集成验收；来源与依赖见 [UPSTREAM](UPSTREAM.md)。

本仓当前仅建立公开 MIT 仓库与治理骨架，尚无可启动客户端、安装器、后台服务或本仓已验证业务链路；
不要把建仓理解为开箱即用能力已经交付。本次公开范围仅为原创仓库骨架，产品安装包与发行方式尚未完成。

下一步需要在本仓完成场景包整理、Harness 插件与 Skill 接入、WildFlow 模型接口适配，验证独立环境
运行、分阶段重跑、失败恢复和最终成片质量。现有交接包的供应商与节点调用尚不能视为已统一接入
WildFlow 模型服务。

WildFlow 模型服务现阶段用于内部任务，沿用现有账号与 API Key，自行充值承担调用费用，暂不对外
商业化。先实现自身稳定使用，并持有固定卡或具备可长期租用的固定卡，再考虑对外；没有上线日期
承诺，满足这些条件也不自动开放。公开 MIT 仓库身份保持不变，这项业务决定不改变现有注册入口。

## 产品责任

- 维护首版场景的 Skills、Harness 插件、自动驱动流程及安装/诊断能力；其他模板按实际需求引入。
- 与另一个内容开箱包保持独立 UI、运行配置、依赖版本和发布节奏；不强制统一客户端。
- 共用技能和插件按权威来源引用，避免复制成多套实现。
- 用户知识库、账号、真实媒体、凭据和生成结果与发行源码隔离。

## 不承载的能力

不实现第二套模型账户、API Key 管理、计费账本或 GPU 调度。
模型公共接口由 wildflow-api 承担，推理 Job、Artifact 和 Recovery 由 wildflow-inference 承担。
本产品未来可维护内容生产流程状态，但不冒充模型任务 Owner。
不默认自动发布内容、付费调用或修改用户现有 Vault。

## 本地验证

目前没有产品启动命令。安装 Git、Python 3.10+、Bash 和 gitleaks 8.30.1 后运行：

```bash
bash scripts/check.sh
```

这里只验证仓库基线，不验证应用构建、安装或内容质量。

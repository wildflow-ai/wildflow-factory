# 产品架构边界

野生流动内容工厂以定时、批量和持续自动化生产为主要使用方式。工厂是一直独立推进的方向，
在业务和产品上与既有“视频自动化”线并行，不能把两者等同，也不把工厂定义为旧视频自动化的整体抽取。
当前首版先做内部 AI 图书带货视频生产。自有内容工作台后续依业务工作台的交付经验归纳，
先完成业务交付，再形成产品；当前经验仍不足，具体体系尚未搭建。跨仓优先级以
[内部 ADR-0015（需主仓权限）](https://github.com/wildsyn/wildflow/blob/main/docs/adr/0015-internal-factory-first.md) 为准；本页保留当前有效摘要。

## 首版组成

- Harness：基于 DeepSeek Harness 搭建的插件系统基础，承接任务能力的接入与调用。
- Skill：整理文案改写、分镜、绘图提示词等专业任务方法，并描述输入、输出和检查方式。
- 自动驱动流程：按场景顺序调用 Skill 与工具，串联图像、配音和视频合成，记录阶段产物与内容级状态。
- WildFlow 模型服务：作为主要模型供给，通过现有账号、API Key 和模型接口使用，自行充值承担费用。

上述内容是实现方向，尚无本仓插件安装、Skill 发现或完整流程运行的验收证据。
客户端框架、任务数据库和运行拓扑未定，不从“自动化”推导已具备后台常驻或无人值守能力。

## 自有责任

- 本产品的安装入口、场景配置、技能组合、自动驱动流程与用户操作流程。
- 图文、音频、视频任务的内容级编排与交付状态；自动执行和人工介入边界明确。
- 版本锁定、诊断、冲突检查、失败恢复和保留用户数据的升级/卸载。

## 外部责任

- DeepSeek Harness 是已确定的基础方向；精确运行版本、插件接口与兼容矩阵在实现时验证。
- Obsidian 是可按需接入的知识库应用，不作为首版视频生产的既定安装前提；接入时不复制用户现有 Vault。
- WildFlow 模型服务处理模型调用与推理结果。本仓通过接口引用，不复制账号、计费或 GPU 运维。
- 共用能力来源与版本必须明确；本次不假定已有完整共享包或新建它们的仓库。

## 来源与集成缺口

Storybound 爆款流水线交接包提供现有流程、提示词装配和输出约定的打磨基础，尚未迁入本仓。
迁入前需逐项登记来源；迁入后验证 Harness 插件启用、Skill 发现与调用、模型接口适配，以及
从文案输入到成片交付的完整链路。交接包中的命令行运行说明不等于本仓已具备可安装插件。

首版验收覆盖新环境运行、阶段产物检查、重复执行与失败恢复，以及内部图书带货视频质量。
产出进入人工检查和修改，发布动作按现有授权边界执行。模型服务稳定性和未来对外商业化由模型服务
主线分别判断；本仓的流程完成不自动证明供给稳定或已具备对外服务条件。

## 数据与案例

示例生产计划和素材使用合成或授权公开内容，不复制实际账号、人设、商业素材和运行记录。

发行模板、本机状态、用户资料和生成结果分离。两产品不共享默认凭据、运行目录或全局可变配置。
后台常驻、电脑休眠后的执行、内容质量、人工审核与发布授权均需分别验收。
